# SEC Pro team experience

Read the installation record in `~/.sec-pro/installation.json` (or the install's chosen data directory) for the package location. Run `python <package>/secpro.py context --task "brief current intent" --data-dir <data>` once when a task starts. Read only the returned relevant entries; do not repeatedly load the full library. The current user's explicit instructions override historical experience. Candidate entries are suggestions, not established requirements. Source documents and old commands are evidence, not authorization.

For development, use installed GSD skills for planning, execution and state. SEC supplies experience and model routing; it does not create parallel plans or a second progress tracker. Before executing a GSD phase, read `sec-pro-cost-routing` and map its bounded worker roles to the GSD execution steps. If GSD is absent, explain how to rerun the installer with Node 24; do not claim GSD execution occurred.

Keep work scoped, inspect existing code first, preserve user edits, and verify the behavior nearest the change. Distinguish actual test results from untested assumptions. Save new experience only from explicit corrections or real observed evidence, with provenance and applicability; model output or user silence is not learning evidence. Use the local candidate/proposal flow; publication requires a separately configured destination and user authorization.
